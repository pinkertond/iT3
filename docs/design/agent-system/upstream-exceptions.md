## Upstream rehearsal

1. Start in an isolated worktree at the last release. Fetch `upstream/main` and record both immutable SHAs. Review native thread contracts, permissions, extension APIs and profile/release behavior for changes.
2. Use `git diff --name-status <previous-upstream-base>..<fork-release>` to check fork-owned additions and every modified upstream path against this register. Compare changes to the recorded paths on upstream, including renames. An unfamiliar upstream edit requires an owner and a disposition before release.
3. Merge the candidate on the rehearsal branch. Prefer upstream equivalents, mark retired entries, and record actual resolution commits and evidence. Run the matrix from the plan with the extension enabled, disabled and absent on the server.
4. After review, follow the existing [release and rollback runbook](../../operations/it3-macos.md). Record tested base, fork tag, API major and store schema in the release evidence. A binary rollback across a schema migration also requires the matching data backup.
